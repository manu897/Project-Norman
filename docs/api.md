# Norman REST API — for Carl-IOS (and the hub)

Norman's HTTP surface has two halves:

- **Read side** — mirrors `Project-Carl-IOS/api/openapi.yaml`. The iOS app uses the same `Node` / `Reading` / `History` shapes whether it's talking to `carl-hub.local` on the LAN or Norman in the cloud. Auth: user JWT.
- **Ingest side** — `POST /v1/hubs/{hub_id}/batch`, the daily HTTPS upload from a Carl hub. Auth: per-hub bearer token. See [ingest-protocol.md](ingest-protocol.md).

The OpenAPI spec is auto-generated by FastAPI:

- Live: `http://localhost:8000/openapi.json`
- Swagger UI: `http://localhost:8000/docs`
- ReDoc: `http://localhost:8000/redoc`

## Endpoints

### Meta
- `GET /health` — liveness probe, no auth.

### Auth (user JWT)
- `POST /v1/auth/register` — email + password → 201 + token.
- `POST /v1/auth/login` — OAuth2 password flow → `{ access_token, token_type }`.

### Hubs (user JWT)
- `GET /v1/hubs` — list hubs the user owns.
- `POST /v1/hubs` — claim a hub. **Response includes `api_token` — shown exactly once. The user provisions this on the hub firmware.**
- `GET /v1/hubs/{hub_id}` — hub metadata + `last_seen_at`.

### Nodes — mirror of hub's `/api/nodes/*` (user JWT)
- `GET /v1/nodes` — every node the user owns across all their hubs, with `latest` reading attached.
- `GET /v1/nodes/{node_id}` — one node's current snapshot.
- `GET /v1/nodes/{node_id}/history?range=24h|7d|30d` — downsampled time series.
  - `24h` → 5-minute buckets, `7d` → 1-hour buckets, `30d` → 6-hour buckets.

### Ingest (per-hub bearer token)
- `POST /v1/hubs/{hub_id}/batch` — see [ingest-protocol.md](ingest-protocol.md).

### Predictions (user JWT)
- `GET /v1/predictions/{hub_id}` — most recent ML output for the hub's nodes. Returns `[]` until the ML pipeline lands.

## What is NOT here vs. the hub

The hub exposes a few endpoints that only make sense on the LAN — Norman intentionally does **not** mirror these:

- `POST /api/setup/wifi` — captive-portal Wi-Fi provisioning, hub-only.
- `GET /api/stream` — WebSocket live stream, hub-only.
- `POST /api/nodes` (the hub's plant-provisioning POST) — handled on the hub, then synced to Norman via the next batch.

## Codegen for iOS

The iOS app codegens a Swift client from the **hub's** `openapi.yaml`. The shared shapes (`Node`, `Reading`, `Calibration`, `History`) appear here unchanged, so the same generated models deserialize Norman responses. Paths differ (`/api/...` on the hub vs. `/v1/...` here) — point the client at whichever base URL is reachable.
